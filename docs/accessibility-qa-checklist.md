# Accessibility QA Checklist

## Mobile Apps

- [ ] Screen reader announces main controls.
- [ ] Touch targets are large enough for primary actions.
- [ ] Text contrast is readable in light and dark mode.
- [ ] Form errors are visible and descriptive.
- [ ] Loading states are announced or clearly visible.
- [ ] Empty states are clear.
- [ ] Status chips include text, not color alone.
- [ ] QR instructions are readable and not hidden by layout.
- [ ] Dynamic text size does not break core screens.

## Admin Web

- [ ] Keyboard navigation reaches all controls.
- [ ] Focus states are visible.
- [ ] Tables are readable and usable at mobile width.
- [ ] Modals trap focus and can close safely.
- [ ] Form labels are associated with inputs.
- [ ] Error messages are placed near the related field.
- [ ] Status colors have text labels.
- [ ] Page headings are structured logically.

## Acceptance

No critical accessibility blocker should remain in login, booking, QR, owner scan, or admin emergency workflows.
