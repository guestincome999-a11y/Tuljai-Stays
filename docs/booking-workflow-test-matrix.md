# Booking Workflow Test Matrix

| Scenario                       | Preconditions                                | Steps                                     | Expected Result                                            | Apps Involved         | APIs Involved                            | Pass/Fail |
| ------------------------------ | -------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------- | --------------------- | ---------------------------------------- | --------- |
| Booking created successfully   | Verified lodge, available room               | Pilgrim selects dates and submits booking | Booking is `PENDING_OWNER_APPROVAL`; owner alert created   | Pilgrim, Owner        | `POST /api/bookings`, booking alert APIs | Pending   |
| Owner accepts                  | Pending booking assigned to owner lodge      | Owner accepts booking                     | Booking becomes accepted; pilgrim receives update          | Owner, Pilgrim        | Owner booking action API                 | Pending   |
| Owner rejects                  | Pending booking                              | Owner rejects with reason                 | Booking becomes rejected; pilgrim sees reason-safe status  | Owner, Pilgrim        | Owner booking action API                 | Pending   |
| Owner does not respond         | Pending booking past deadline                | Wait for scheduler                        | Booking expires or moves to configured timeout state       | Backend, Pilgrim      | Scheduler, booking APIs                  | Pending   |
| Admin manually accepts         | Pending/overdue booking                      | Admin updates status with reason          | Booking moves to accepted; audit log written               | Admin, Pilgrim, Owner | Admin booking control API                | Pending   |
| Admin manually rejects         | Pending/overdue booking                      | Admin rejects with reason                 | Booking moves to rejected; audit log written               | Admin, Pilgrim        | Admin booking control API                | Pending   |
| Booking expires                | Active lock or pending booking passes expiry | Run scheduler or wait                     | Expired state visible; room availability released          | Backend, Pilgrim      | Scheduler, booking APIs                  | Pending   |
| Booking transferred foundation | Transfer-capable booking context exists      | Admin initiates transfer foundation path  | Transfer foundation handles unsupported persistence safely | Admin                 | Admin booking APIs                       | Pending   |
| Room unavailable after lock    | Room locked then made unavailable            | Pilgrim attempts final submit             | Booking is blocked with clear error                        | Pilgrim, Backend      | Availability and booking APIs            | Pending   |
| Duplicate booking attempt      | Same pilgrim/date/lodge context              | Submit duplicate request                  | Duplicate is rejected or handled safely                    | Pilgrim               | Booking API                              | Pending   |
| Offline booking attempt        | Device offline                               | Pilgrim submits booking                   | App shows offline/error state; no duplicate created        | Pilgrim               | Local client, booking API                | Pending   |
| Invalid guest count            | Guest count above capacity or invalid        | Submit booking                            | Validation error shown                                     | Pilgrim, Backend      | Booking API                              | Pending   |
| Invalid dates                  | Past or reversed dates                       | Submit booking                            | Validation error shown                                     | Pilgrim, Backend      | Booking API                              | Pending   |
| Owner offline                  | Owner app disconnected                       | Booking is created                        | Booking persists; owner sees on reconnect/manual refresh   | Pilgrim, Owner        | Booking, notifications, realtime         | Pending   |
| Realtime update failure        | Socket disconnected                          | Change booking status                     | REST refresh still shows correct state                     | Pilgrim, Owner, Admin | Booking APIs, Socket.IO                  | Pending   |
| Notification failure           | FCM unavailable                              | Trigger booking event                     | Booking state still changes; delivery log records failure  | Backend, Apps         | Booking and notification services        | Pending   |
